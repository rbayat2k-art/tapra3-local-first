# Feature Specification: جست‌وجوی مسیرها و پرکاربردهای شخصی

**Feature Branch**: `fix/ocr-blockers-20260824`

**Created**: 2026-08-25

**Status**: Approved implementation scope

## Goal

کاربر بتواند از منوی اصلی نام صفحه یا فرم عملیاتی مانند «مساعده»، «پرسنل» یا «درخواست خرید» را جست‌وجو کند و مستقیماً به مقصد دقیق و مجاز برود. داشبورد نیز فقط مسیرهایی را که همان کاربر واقعاً بیشتر استفاده کرده است نشان دهد.

## Actors

- کاربر واردشده: جست‌وجو و مشاهده فقط مقصدهای مجاز هویت مؤثر خودش.
- کاربر دارای چند نقش یا مجوز زیاد: دسترسی سریع به صفحه یا زیربخش دقیق بدون بازکردن گروه‌های متعدد.
- ادمین در حالت مشاهده آزمایشی: مشاهده منوهای هویت هدف، بدون ثبت یا افشای سابقه استفاده شخصی او.

## Functional requirements

- **FR-001**: یک کاتالوگ مشترک از صفحه‌های اصلی و زیربخش‌های واقعی `ERP_MODULES`، منبع جست‌وجو و پرکاربردها باشد.
- **FR-002**: نتیجه صفحه فقط وقتی دیده شود که همان منطق فعلی `visibleNavigation` آن را مجاز بداند؛ نتیجه زیربخش حتماً مجوز `view` همان module را بخواهد.
- **FR-003**: جست‌وجو فاصله، نیم‌فاصله، `ي/ی`، `ك/ک` و حروف انگلیسی را نرمال کند و aliasهای روشن «پرستل/پرسنل»، «مساعده» و «درخواست خرید» را بشناسد.
- **FR-004**: انتخاب نتیجه، URL دقیق `page` و در صورت نیاز `module` را ثبت کند؛ refresh، back/forward و تغییر module در همان page مقصد صحیح را نگه دارند.
- **FR-005**: «پرکاربردهای من» فقط از انتخاب‌های ارادی منو، جست‌وجو، میان‌بر داشبورد یا تب module ساخته شود؛ refresh، back/forward و redirect سیستمی شمارش نشوند.
- **FR-006**: usage به‌صورت preference نسخه‌دار در `localStorage` و جدا برای هر `activeUser.id` نگهداری شود؛ فقط destination id، count و lastUsedAt ذخیره شود و query/PII ذخیره نشود.
- **FR-007**: رتبه‌بندی ابتدا بر اساس count، سپس زمان آخرین استفاده و حداکثر ۶ مقصد باشد. مقصد بدون استفاده واقعی به‌عنوان «پرکاربرد» ساخته نشود.
- **FR-008**: مقصدهای dashboard، حساب/امنیت، تنظیمات ظاهری، QA، Audit و مدیریت داده در usage عملیاتی شمارش نشوند.
- **FR-009**: در QA/impersonation هیچ usage خوانده یا نوشته نشود. با تغییر هویت، نتایج و usage همان لحظه از هویت جدید محاسبه شوند.
- **FR-010**: لغو مجوز، نتیجه و میان‌بر مربوط را بدون افشای عنوان پنهان کند؛ metadata محلی برای بازگشت احتمالی مجوز حفظ شود ولی منبع authorization نباشد.
- **FR-011**: خرابی، quota یا نبود localStorage نباید navigation را متوقف کند؛ فقط personalization به empty state برگردد.
- **FR-012**: نام نمایشی جاری محصول در runtime، عنوان مرورگر، خروجی چاپی و پیام‌های جدید به «تیرا/Tira» تغییر کند. شناسه‌های persisted/compatibility شامل `tapra2_local`، snapshot format، package، company/internal IDs، credential و کلیدهای قدیمی storage دست‌نخورده بمانند.
- **FR-013**: تاریخچه/audit قدیمی به‌عنوان حقیقت تاریخی بازنویسی نشود؛ seed و copy جدید «تیرا» باشند.

## Acceptance criteria

1. جست‌وجوی «مساعده» برای کاربر مجاز، مقصد مساعده را نشان می‌دهد و Enter به `page=hcm&module=employee-advance` می‌رود؛ refresh همان tab را نگه می‌دارد.
2. جست‌وجوی «درخواست خرید» فقط برای کاربر دارای view همان module نتیجه می‌دهد و به `page=procurement&module=purchase-request` می‌رود.
3. «پرسنل» برای کاربر دارای مجوز یا supervisor واجد رابطه دیده می‌شود و برای actor فاقد هر دو دیده نمی‌شود.
4. ArrowUp/Down، Enter و Escape کار می‌کنند؛ تعداد نتیجه announce می‌شود؛ sidebar جمع‌شده امکان بازکردن search دارد و در موبایل انتخاب نتیجه منو را می‌بندد.
5. پس از استفاده واقعی، داشبورد حداکثر ۶ مقصد مجاز را با ترتیب deterministic نشان می‌دهد؛ reload حفظ و user switch آن را جدا می‌کند.
6. مقصدی که مجوزش حذف شده نه در search و نه در frequent دیده نمی‌شود؛ URL مستقیم unauthorized به fallback مجاز می‌رود.
7. در حالت QA، tracking خاموش و بخش frequent خالی/غیرشخصی است.
8. payload localStorage هیچ query، title یا داده رکورد ندارد و خرابی storage مانع navigation نمی‌شود.
9. رابط RTL و mobile بدون overflow و بدون تخلف serious/critical accessibility است.
10. هیچ نام قدیمی user-visible در runtime فعال، print و recovery copy باقی نمی‌ماند، در حالی که DB، snapshot و preferences قبلی همچنان سازگارند.

## Out of scope

- جست‌وجوی داخل محتوای رکوردها یا نمایش داده عملیاتی در sidebar.
- تغییر permission، scope یا workflow برای ایجاد دسترسی جدید.
- sync پرکاربردها بین دستگاه‌ها یا ثبت آن در Audit.
- بازنویسی تاریخچه‌های persisted، تغییر نام IndexedDB، package، snapshot format، شناسه‌ها و رمزهای demo.
- بازکردن خودکار فرم ایجاد؛ نتیجه به صفحه/زیربخش دقیق می‌رود و ایجاد رکورد همچنان اقدام صریح و permission-checked خود module است.
