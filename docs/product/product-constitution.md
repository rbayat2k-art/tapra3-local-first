# قانون اساسی محصول TAPRA3

> **وضعیت:** `CURRENT` — این سند قواعد پایدار محصول را بیان می‌کند؛ جزئیات دامنه باید از سند همان دامنه و کد/تست فعال تأیید شود.

## MUST — الزامی

- تجربه کاربر فارسی، RTL، واکنش‌گرا و قابل استفاده با صفحه‌کلید باقی بماند.
- Runtime جاری به‌عنوان برنامه مرورگرمحور Local-first با IndexedDB در نظر گرفته شود؛ معماری Server/PostgreSQL تاریخی، قابلیت فعال نیست.
- تاریخ در UI طبق الگوی جاری شمسی نمایش/انتخاب و مقدار عملیاتی در Storage به‌صورت ISO ذخیره شود.
- هر فرمان حساس در لایه سرویس، Permission، Scope، مالکیت Resource، Workflow و Maker/Checker را enforce کند؛ پنهان‌کردن دکمه کافی نیست.
- تغییر مهم کسب‌وکار History، Actor، Effective User، زمان، Reason و Audit متناسب داشته باشد و مقدار حساس را وارد Audit نکند.
- رکوردهای تاریخی، نسخه‌ها و lineage با تغییر وضعیت/نسخه حفظ شوند؛ حذف فیزیکی فقط با تصمیم صریح محصول و سیاست retention مجاز است.
- تغییر چند Store که یک نتیجه کسب‌وکار واحد می‌سازد، اتمیک یا Saga پایدار، idempotent و قابل Retry باشد.
- Migration افزایشی، idempotent و دارای تست از fixture واقعاً قدیمی باشد؛ داده کاربر یا Workflow تاریخی نباید با Seed جدید جایگزین شود.
- هر Business Rule نامشخص به‌عنوان `NEEDS PRODUCT DECISION` متوقف شود؛ Agent حق حدس‌زدن ندارد.
- هیچ کار با سؤال محصولی حل‌نشده یا Gate الزامی ناموفق «تمام‌شده» اعلام نشود.

## SHOULD — ترجیح قوی

- Feature از مسیر Requirement → Domain/Architecture → UI plan → Implementation → Test → Independent review عبور کند.
- Component، الگوی فرم، جدول، Modal، Validation و Empty/Loading/Error موجود قبل از ساخت نمونه جدید reuse شود.
- تست منفی دسترسی، stale version، reload/persistence و failure path متناسب با ریسک Feature نوشته شود.
- تغییرات در کامیت‌های کوچک و قابل‌بازگشت و روی Branch غیرمحافظت‌شده انجام شود.
- اسناد نزدیک به رفتار در همان تغییر به‌روز شوند و برچسب `Verified/Planned/Deprecated/Conflict` صادق بماند.

## MAY — اختیاری با دلیل

- Shared component جدید وقتی حداقل دو مصرف‌کننده واقعی دارد یا consolidation آن صریحاً تصویب شده باشد.
- ابزار/Dependency جدید وقتی Gap مشخصی را می‌بندد، با Stack فعلی تداخل ندارد و Gate قابل تکرار ایجاد می‌کند.
- Agent تخصصی فقط وقتی فعال شود که ریسک یا حجم Task ارزش هزینه زمانی/توکنی را داشته باشد.

## مرز تصمیم محصول

Agent می‌تواند رفتار موجود را کشف و تناقض را گزارش کند، اما درباره سیاست مالی، منابع انسانی، retention، SoD، SLA، داده حساس یا تجربه جدید کاربر بدون شاهد معتبر تصمیم نهایی نمی‌گیرد.
