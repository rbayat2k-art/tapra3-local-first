# پاسخ به رخداد

> **وضعیت سند:** `Documented` — Runbook پیشنهادی برای محصول محلی

## دسته‌بندی

| سطح | نمونه |
|---|---|
| P1 | از دست رفتن یا افشای داده حساس، Restore مخرب، دسترسی غیرمجاز گسترده |
| P2 | ناتوانی در ورود/پرداخت/تأیید یا فساد یک گردش مهم |
| P3 | خطای محدود UI، Sorting، چاپ یا گزارش |

## اقدام فوری

1. عملیات تغییردهنده را متوقف و صفحه/نسخه/زمان/شناسه رکورد را ثبت کنید.
2. اگر داده قابل دسترس است Snapshot رمزگذاری‌شده بگیرید؛ Reset نکنید.
3. Audit، Domain Event و Workflow History مرتبط را با correlation ID بررسی کنید.
4. روی داده کپی یا پروفایل مرورگر جدا بازتولید کنید.
5. علت، دامنه اثر، راه‌حل موقت و تصمیم بازیابی را ثبت کنید.

## سناریوهای رایج

- **تعارض چندتب:** Refresh، بررسی نسخه جدید، تکرار آگاهانه فرمان.
- **Import ناموفق:** فایل اصلی را تغییر ندهید؛ schema/checksum/password را بررسی کنید.
- **داده ناقص پس از Reset:** فقط از Backup معتبر Restore کنید.
- **مجوز اشتباه:** نقش‌ها، override، scope، وضعیت کاربر و route frozen رکورد را بررسی کنید.
- **گردش گیرکرده:** assignee فعلی، نقش scoped فعال، stage/route و history را بررسی کنید؛ رکورد را دستی در IndexedDB دست‌کاری نکنید.

## پس از رخداد

`Documented` — Timeline، علت ریشه‌ای، کنترل جلوگیری، تست regression، اثر داده‌ای و تصمیم Product Owner ثبت شود. اگر incident امنیتی است فایل Snapshot یا PII در Issue عمومی قرار نگیرد.

`Unknown` — کانال تماس، Incident Commander، SLA پاسخ و الزام گزارش قانونی سازمان تعیین نشده است.
